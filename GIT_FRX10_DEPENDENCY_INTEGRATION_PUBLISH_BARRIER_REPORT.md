# GIT-FRX-10 — Dependency-aware integration + prepare/publish barrier

Date: 2026-09-25
Roadmap milestone: GIT-FRX-10
Target: `devtool`
Native workflow: `roadmap-git-frx10`
Apply mode: interim / `--no-validate`

## Delivered contract

GIT-FRX-10 keeps child validation/result creation separate from integration into user-owned branch pointers. Federation consumes the existing FRX-Y02 parent checkpoint plus GIT-FRX-09 lineage and applies one of the declared policies:

- `per-repo`
- `dependency-group`
- `all-or-nothing-pointer-update`

Integration is explicit through `devtool federation integrate RUN_ID`. It defaults to dry-run; mutation requires `--apply` and the normal Devtool confirmation contract (`-y/--yes` for non-interactive use). Federation never pushes automatically.

Release workflows may opt into `publish_barrier=true` and mark workflow steps as `prepare` or `publish`. Every publish node is dependency-gated by every prepare node. A failed or missing prepare node keeps the barrier closed and blocks child-owned publish nodes. Federation owns only barrier/evidence truth; it does not own a child release operation and does not roll back an already-published release.

## Integration safety

Validated child lineage remains authoritative. Integration accepts only local `refs/heads/*` targets with available start/result commits and a fast-forward relationship. It refuses branch drift, dirty checked-out worktrees, active Git operations, missing repositories, failed validation, inconsistent branch refs, and unavailable lineage commits.

Checked-out branches are advanced with `git merge --ff-only`; non-checked-out branches use compare-and-swap `git update-ref REF NEW OLD`. Grouped policies roll back only pointers already moved within the failing integration group. Unrelated dependency groups are not rewritten. Untracked Devtool-owned `.devtool/` runtime evidence is ignored for cleanliness because it is generated by Devtool itself; tracked/index changes and user untracked files remain blockers, and Git still rejects any untracked-file overwrite during fast-forward.

Integration evidence is persisted under Devtool state as `devtool.federation.git-integration`. It records policy, pointer pre/post identities, group results, dry-run/apply state, evidence digest, `automatic_push=false`, and `published_release_rollback_owned=false`.

## Audit loop findings and fixes

The audit loop found and fixed four material issues before packaging:

1. machine completion expected-order drift after adding the new target-local fixture;
2. barrier injection could create a prepare↔publish cycle when prepare already depended on publish, now rejected fail-closed;
3. checked-out worktree detection compared short Git branch names to canonical `refs/heads/*`, which could bypass dirty-worktree protection;
4. inactive Git-operation metadata was initially treated as active, and Devtool-owned untracked runtime evidence could falsely block a clean validated checkout.

Additional safety contracts prove dependency-group isolation, rollback after a simulated pointer-update failure, dirty checked-out branch refusal, and the failed-consumer publish-barrier invariant.
