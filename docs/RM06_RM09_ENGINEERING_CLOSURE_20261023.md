## Operator example

```sh
devtool -r "$HOME/Code/my-project" actions provider-export \
  --mode multi-job --affected --workflow ci \
  --affected-base HEAD~1 --devtool-sha "$(git -C "$HOME/Code/devtool" rev-parse HEAD)" \
  --plan
```

Remove `--plan` to obtain the same read-only JSON plan. Use `--yes` only on a clean reviewed consumer checkout; this creates workflow files but never pushes, dispatches, authenticates or signs them. Use `--verify` to compare generated bytes. The native DAG for each selected target remains authoritative.

## Termux native validator portability correction (2026-10-23)

The first supplement was locally accepted on Linux but failed its embedded pytest
validator on the user’s Termux device: `test_poetry_pdm_native_network_denial_and_fail_closed`
expected the simulated offline sync error, but the *real* Termux interpreter
rejected the unsupported network-namespace host first. This is valid runtime
fail-closed behavior, not evidence that the native manager escaped isolation.

The corrected regression mocks **only the host-capability decision** for its
simulated Linux `unshare` branch, without changing the actual runtime host gate,
tracked lock verification, subprocess command or failure semantics. Separate
parameterized Android/unsupported-host tests assert refusal *before any
subprocess or environment creation*. The same test suite now exercises both
policy branches on any OS and continues to require real hosted receipts for
positive Poetry/PDM qualification. The original failed Termux acceptance is
recorded, not silently rewritten to PASS.
