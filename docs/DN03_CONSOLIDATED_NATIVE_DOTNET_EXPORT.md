# DN03-R1 — Consolidated native .NET export and source/host receipts

Base: `Mikeyphw/devtool` commit `c24fad016cfb2526b14ddae58237aea883df9f13` (merged DN02 PR #3).

## Scope actually implemented

* **One native Devtool overlay**, rather than a chain of ad-hoc source patch scripts. The schema-v2 artifact has an exact Git base-tree contract, a complete checksum inventory, a mandatory validator, and a **manifest-enabled Git commit**.
* A reusable source-bound .NET-only hosted exporter, invoked as `python3 -m devtool.actions_dn03_dotnet` from an installed or checked-out Devtool package. It delegates all node ownership, dependency edges, toolchain admission, source checks and runtime execution to RM-06's existing `compile_graph`, `workflow_yaml` and `run_node`. It does not invent a second scheduler.
* `plan` is read-only; `write --yes` requires a clean Git worktree, refuses any existing destination, and verifies that HEAD does not change during the transaction; `verify` regenerates the graph and compares exact workflow and receipt bytes. No force/overwrite option is provided.
* Generated workflows retain immutable setup action pins, per-node source-frozen runner behavior and existing byte/evidence handoffs. The DN03 step **verifies actual installed SDK** and, for opted-in .NET 6 jobs, the exact **Microsoft.NETCore.App 6.0.36** runtime. It writes a local host review receipt with source, graph, run, attempt and node identifiers, then uploads that receipt with the immutable upload-artifact action. Missing receipts fail the job; this is not independent GitHub authentication or release attestation.
* Regression tests cover determinism, YAML structure, unsafe paths and source pins, unsupported runtime or mixed providers, clean-tree guarded writes, duplicate anchors and tampering. A source-only GitHub Actions workflow executes these alongside DN01/DN02/RM09/FC06 tests.

## Generate for a configured consumer

The consumer must already have an RM-09 eligible native target-local .NET workflow, tracked `global.json`, tracked NuGet lockfiles, and clean Git source. The `--devtool-sha` must be an **exact 40-character commit of the Devtool version used for the hosted runtime**, not `main` or a floating tag.

```sh
cd "$HOME/Code/my-consumer"
PIN="$(git -C "$HOME/Code/devtool" rev-parse HEAD)"
python3 -m devtool.actions_dn03_dotnet plan \
  --repo "$PWD" --target TARGET --workflow WORKFLOW --devtool-sha "$PIN"
python3 -m devtool.actions_dn03_dotnet write \
  --repo "$PWD" --target TARGET --workflow WORKFLOW --devtool-sha "$PIN" --yes
python3 -m devtool.actions_dn03_dotnet verify \
  --repo "$PWD" --target TARGET --workflow WORKFLOW --devtool-sha "$PIN"
```

`write` adds `.github/workflows/devtool-dn03-TARGET-WORKFLOW.yml` and `docs/ci/devtool-dn03-TARGET-WORKFLOW.json` to the consumer. Review and commit these **in the consumer** separately. This command does not dispatch, push or sign anything.

The deterministic review receipt excludes the consumer HEAD so the generated workflow remains verifiable after its own Git commit. The native provider-plan and graph digests still bind the reviewed source/lock bytes, while runtime receipts include the actual GitHub source SHA.

The generator supports only Linux amd64 .NET-only DAGs for now. Unknown SDKs, non-`.NET` jobs, Windows/macos nodes, unreviewed EOL runtime versions, and absent/changed RM-06 workflow anchors are rejected.

## Explicit remaining DN03/R06d work

1. **Runtime-only** .NET 6 installation is not asserted here. The inherited DN02 exporter still installs pinned SDK 6.0.428 to supply runtime 6.0.36; replacing that with an independently digest-verified runtime-only installation needs reviewed Microsoft release hash metadata and real hosted acceptance. No unverified download URL/sha is introduced by this overlay.
2. Host receipts generated by a workflow are local evidence bound to its declared GitHub context, not an independent authentication of that context. A future provenance layer must verify authentic run/attempt/artifact attestations and their trust roots.
3. Real Windows-only `net6.0-windows` hosted execution, cross-provider DAG fanout, and R06d native consumer acceptance are **not qualified** by Python unit tests or the existing DN02 standalone hosted compatibility run.
4. The source-gate job is not a release pipeline; it cannot verify that arbitrary generated consumer workflows run on GitHub. A separate consumer-hosted run is required.

## Overlay application

Apply only against clean Devtool `main` at the exact base commit above:

```sh
cd "$HOME/Code/devtool"
git fetch origin main
git switch main
git merge --ff-only origin/main
test "$(git rev-parse HEAD)" = c24fad016cfb2526b14ddae58237aea883df9f13

devtool --repo "$PWD" --yes apply-overlay \
  /storage/emulated/0/Download/DEVTOOL_DN03_R1_CONSOLIDATED.overlay.zip \
  --keep-artifact

git log -1 --oneline
git status --short
git push origin main
```

**Commit is deliberately in `.devtool-artifact.json`** (`apply.commit.enabled=true`, `strategy=single`, exact message). Do not run a separate `git commit` unless validation reported a validated-but-uncommitted transaction. The artifact's embedded bash validator runs the new regression tests and source checks before the commit. Use `--yes` for unattended confirmation.
