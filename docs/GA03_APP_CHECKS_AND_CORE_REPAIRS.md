# GA-03: independent App Check evidence and core recovery repairs

The three Check Run names are `Devtool / Source Validation`, `Devtool / Integration Qualification`, and `Devtool / Federation Compatibility`. They supplement, not replace, independent Actions qualification. Do not configure them as required branch checks merely by publishing them. They do not authorize merge, signing, or release.

Native entry point: `python3 -B -m devtool.ga03_checks --session-id SESSION --kind source|integration|federation --attempt 1 --policy FILE --policy-sha256 DIGEST`. Omit `--yes` for read-only preview/reconciliation. Explicit `--yes` approves only the exact Check Run in the enrolled repository. Each attempt binds repository ID, exact commit, session, class, attempt and source-bound GA-02 policy. It uses a dedicated scoped App read/write capability, never falls back to a PAT, and never persists the credential. Source Validation reattests original native required validation/history. Integration Qualification independently reads the required Actions run/attempt and jobs, not any App check result. Federation Compatibility reports the configured native Gate 2 planning/compatibility evidence with explicit relationship and remote source pins, not downstream consumer CI; standalone projects receive neutral. Missing/uncorroborated Actions evidence is neutral, not green. Annotations are bounded and fixed, on a committed configuration file only; details URL is the exact GitHub commit.

Before POST or PATCH, the native delivery session persists its intent. A lost response is read-only reconcile; a missing or ambiguous result is never permission to retry. An independently matched in-progress creation can be adopted without replay and completed on a subsequent separately approved invocation. Stale/duplicate attempts, scope mismatches, changed source and foreign check identity refuse. An attempt already confirmed is reverified without writes. An old confirmed check is historical evidence, not approval for changed evidence. A fresh attempt requires a different evidence digest. Release remains separate.

For live qualification use only an explicitly approved disposable branch/session and GA-02 owner-approved policy with its exact commit and repository/installation IDs. Preview first; approve publication; verify read-only afterward. Do not change production rules, workflows, App grants or installation selection. GA-03 live security acceptance is pending until actual disposable Check Runs are independently observed. Test stale attempts/duplicates/foreign identity locally without deliberately corrupting live checks.
