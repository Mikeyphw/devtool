Project selection:
  -r, --repo REPO       Repository root
  -c, --config CONFIG   Config file path
  --target TARGET       Named target/profile from .devtool.toml
  --group GROUP         Workspace target group from [workspace.groups];
                        repeatable
  --all-targets         Select every configured workspace target
  --affected            Select workspace targets affected by current Git
                        changes; may be combined with --group/--all-targets as
                        a candidate filter
  --affected-base AFFECTED_BASE
                        Git base revision for --affected selection (default:
                        staged/unstaged/untracked working tree)
  --affected-head AFFECTED_HEAD
                        Git head revision for --affected selection; with
                        --affected-base uses base...head
  --variant VARIANT     Build/test variant within the selected target
  --solution SOLUTION   Exact solution path for restore/build/test
  --project PROJECT     Exact project path for run/validation
  --runner, --project-type {auto,dotnet,android,gradle,python,node,rust,go,maven,cmake,meson,make,command,unknown}
                        Override the project runner for this run; --project-
                        type remains a compatibility alias

Execution:
  -v, --verbose         Stream full command output
  -q, --quiet           Suppress normal human output; errors still print
  --trace               Enable architecture event tracing and full exception
                        tracebacks
  -y, --yes             Assume yes for confirmations
  -f, --force           Force dangerous actions
  --allow-pending-validation
                        Allow a new operation while another artifact remains
                        pending validation; rollback state is preserved
  --dry-run             Print commands without running them
  --no-build            For test: pass --no-build to dotnet test
  -k, --continue-on-error
                        Continue with the next independent step after an error
  --fail-fast           Stop at the first failed step
  --performance         Write a JSON performance report for this run
  --performance-file PERFORMANCE_FILE
                        Performance report path (default: devtool state
                        directory)

Execution environment:
  --host                Force command phases to run in devtool's current host
                        environment
  --chroot CHROOT       Run command phases inside a named chroot via chrootctl
                        exec
  --ssh, --ssh-host HOST
                        Use HOST as the SSH execution target (whole devtool or
                        command-phase mode)
  --ssh-profile NAME    Use a named SSH worker from [ssh.hosts.NAME]; explicit
                        SSH flags override profile fields
  --proot-distro DISTRO
                        Run command phases inside a PRoot-Distro container;
                        guest does not need devtool
  --execution-environment {auto,native-termux,chroot,desktop-linux,android-device,external-device,ssh,proot-distro}
                        Execution backend: auto, native-termux, chroot, proot-
                        distro, desktop-linux, ssh, android-device, or
                        external-device
  --ssh-port PORT       SSH port (default: 22 or [ssh].port)
  --ssh-user USER       SSH login user
  --ssh-identity PATH   SSH private-key identity file
  --ssh-session NAME    tmux session name; stable names can be reattached
  --ssh-cwd PATH        Working directory on the SSH host; omitted means the
                        remote login default
  --ssh-tool COMMAND    Remote devtool executable used by --ssh-mode devtool
                        (default: devtool)
  --ssh-mode {devtool,commands}
                        SSH mode: delegate the whole devtool run, or keep
                        devtool local and run command phases remotely
  --ssh-stage-dir PATH  Remote staging root for copied overlays/helper files
  --ssh-no-artifact-copy
                        Disable automatic SSH/SCP artifact transfer
  --ssh-detached        Start/reuse the remote tmux session without attaching
                        (whole-run devtool mode)
  --proot-user USER     PRoot-Distro guest user (default: root or
                        [proot].user)
  --proot-cwd PATH      Initial absolute working directory inside the PRoot
                        guest
  --proot-repo-mount PATH
                        Absolute guest mount point for the current repository
  --proot-bind HOST:GUEST
                        Additional PRoot bind; repeatable, guest destination
                        must be absolute
  --proot-env NAME=VALUE
                        Explicit environment variable passed to the PRoot
                        guest; repeatable
  --proot-no-auto-bind-repo
                        Do not automatically bind the repository into the
                        PRoot guest
  --proot-shared-home   Ask PRoot-Distro to share the host home with the guest
  --proot-shared-tmp    Ask PRoot-Distro to share Termux tmp with the guest
  --proot-isolated      Use PRoot-Distro isolated mode (Termux hosts only)
  --proot-minimal       Use PRoot-Distro minimal mode (Termux hosts only)
  --proot-stage-dir PATH
                        Host staging directory bound into the PRoot guest
  --termux-resource-profile {auto,automatic,conservative,balanced,performance,off,none}
                        Termux resource defaults for workers/JVM/native
                        concurrency; off/none bypasses automatic Termux
                        resource defaults
  --no-termux-resource-profile
                        Bypass automatic Termux resource defaults for this
                        invocation
  --termux-wake-lock    Acquire a Termux wake lock while command phases run
  --no-termux-wake-lock
                        Disable Termux wake-lock integration for this run
  --shared-storage-policy {allow,warn,deny}
                        Policy for repositories on Android shared storage
  --allow-shared-storage-build
                        Allow a build from Android shared storage for this run
  --artifact-export DIR
                        Copy verified artifacts to DIR after successful local
                        verification
  --no-auto-chroot      On Termux, do not auto-route command phases through
                        chrootctl

Common workflows:
  devtool -r REPO validate
  devtool -r REPO apply-overlay PATCH.zip --validate --commit MESSAGE
  devtool -r REPO apply-overlays BUNDLE.zip --validate --commit MESSAGE

Multiple overlays run sequentially: each overlay is applied, validated, and committed before the next starts.
