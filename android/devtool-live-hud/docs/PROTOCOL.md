# Devtool Live HUD broadcast protocol

## Component

```text
io.github.mikeceead.devtoolhud/.BridgeReceiver
```

## Actions

- `io.github.mikeceead.devtoolhud.UPDATE`
- `io.github.mikeceead.devtoolhud.COMPLETE`
- `io.github.mikeceead.devtoolhud.FAIL`
- `io.github.mikeceead.devtoolhud.CANCEL`

## Required extras

- `token` (`String`) — token generated by the setup activity.
- `run_id` (`String`) — stable logical devtool run identifier.

## Progress extras

- `status` (`String`): `running`, `waiting`, `ok`, `failed`, `interrupted`, `cancelled` or `skipped`.
- `phase`, `detail`, `repo`, `target`, `commit`, `summary` (`String`).
- `progress`, `current`, `total`, `passed`, `failed`, `skipped`, `warnings`, `errors` (`int`).
- `started_at_ms`, `duration_ms` (`long`).
- `indeterminate` (`boolean`).
- `overlay` (`boolean`) — request inclusion in the optional floating overlay. Defaults to false.

Notifications are always posted. Overlay rendering additionally requires:

1. `overlay=true` on the run update;
2. display-over-other-apps permission;
3. the user-enabled foreground overlay service.

The overlay service is intentionally not enabled by broadcasts alone.
